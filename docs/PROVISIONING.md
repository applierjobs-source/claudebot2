# DigitalOcean Provisioning Approach

## MVP: Single Droplet, Multiple Containers

1. **Pre-create one Droplet** (or create on first bot):
   - Ubuntu 22.04, Docker pre-installed (use DO Docker one-click or user data script).
   - Backend stores droplet id in config or in a `droplets` table (id, host, status, capacity).

2. **Create Bot flow**:
   - Backend creates `bots` row (status: `pending`).
   - Backend picks a droplet (e.g. the single one); if none, create via DO API.
   - Backend SSHs or uses DO Docker API to run container:
     - Image: `ghcr.io/<org>/claudebot-agent:latest`
     - Env: `BOT_ID`, `API_URL`, `LOG_TOKEN` (or JWT for bot), `CONFIG_JSON` (template + overrides).
   - Backend updates `bots` with container_id, status: `running`.
   - Container starts agent process; agent POSTs logs to `API_URL` with `LOG_TOKEN`; backend validates and stores in `bot_logs`.

3. **Stop Bot**:
   - Backend sets status to `stopped`; optionally SSH/DO API to stop container (docker stop).

4. **Restart Bot**:
   - Same as create but reuse droplet; docker start or docker run with same config.

5. **Delete Bot**:
   - Stop container; remove container; set bot status to deleted or remove row.

## DO API Usage

- **Create droplet**: `POST /v2/droplets` with name, region, size, image, optional user_data (install Docker).
- **Get droplet**: `GET /v2/droplets/:id` for IP.
- **Delete droplet**: `DELETE /v2/droplets/:id` (when scaling down).

For MVP, running containers on existing droplet can be done by:
- **Option A**: Backend has a small “worker” service that runs on the same droplet and receives “run this container” commands from API (over authenticated channel).
- **Option B**: Backend uses DO API + user_data or a one-time setup script that installs Docker and a simple API listener on the droplet to run containers (custom agent).
- **Option C (simplest for MVP)**: Backend uses SSH (or DO floating “execute command”) to run `docker run ...` on the droplet. Store SSH key in secrets.

We'll use **Option C** for MVP: one droplet, SSH from Railway backend to run `docker run` / `docker stop` / `docker rm`.

## Security

- One SSH key per droplet (or shared); stored in Railway secrets; not in repo.
- LOG_TOKEN: per-bot token generated by backend, passed to container; backend validates on each log request.
